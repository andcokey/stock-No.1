ドラッグ&ドロップ→自動集計→ダッシュボード表示に置き換える。
テイスト参照: https://andcokey.github.io/kokkaigiin-kankei-db/index.html

`取組記入用` シート: 会社単位・月次の `売上/粗利/営業利益/粗利率/営業利益率/ストック売上/ストック粗利/ストック営業利益/ストック粗利率/ストック営業利益率/ストック比率/施策・取り組み`（自由記述）。

### 1.2 集計ファイル（3、ファイル名 `901_ストック強化_集計シート_yyyymmdd.xlsm`）

関係するシート:
- `見通yyyymmdd`: 50ファイルの `商材集計` を縦に連結しただけのシート（週替わりで新規作成）
- `目標`: `見通yyyymmdd` と同一レイアウトだが、値が年間予算（目標値）
- `901_会社集計`: 会社別の 売上高／ストック売上額／ストック比率 を「目標」「見通（今週）」「目標差異」で月次・通年比較
- `902_商材見通集計`: 商材別の成長ステージ4象限分類＋KPI時系列（詳細は2.2）
- `903_対目標売上` / `対目標スト売上`: 商材別・月次の対目標差異（売上高／ストック売上）

## 2. 集計ロジック仕様（数式を読み解いて確定）

### 2.1 901_会社集計相当

会社ごとに、その週の `見通yyyymmdd` シートの `（会社）売上高` `（会社）ストック売上額` 行から月次値を取得し、
`目標` シートの同一会社・同一項目（集計用コード一致）を `SUMIFS` で引いて比較するだけ。

```
売上高.目標[会社][月]  = SUMIFS(目標データ, 会社コード一致, 集計用コード=1)
売上高.見通[会社][月]  = 当該週の見通データから直接取得（各ファイルの（会社）売上高行）
売上高.差異[会社][月]  = 見通 - 目標
ストック比率[会社][月] = ストック売上額 / 売上高
```

会社レベルでは商材別の内訳は不要（各社ファイル自身が商材の合計を「（会社）」行として既に計算済みのものを使う）。

### 2.2 902_商材見通集計相当（4象限分類ロジック）

商材ごとに以下3つの二値評価を計算する。「25評価」は直近1年の**実績**、「26評価」は今後1年の**見通**に対して同じロジックを適用。

| 評価軸 | 実績（25評価）の算出 | 見通（26評価）の算出 |
|---|---|---|
| 継続率評価 | 直近月の `顧客継続率（新規）` ≥ 75% → ○、それ未満 → × | 見通12ヵ月平均の `顧客継続率（新規）` ≥ 75% → ○／× |
| 増加数評価 | 直近月の `顧客増加数` > 0 → ○／× | 見通最終月の `顧客増加数` > 0 → ○／× |
| 売上増加評価 | （直近月売上）－（前年同月売上）> 0 → ○／× | 見通12ヵ月の前年同月増加量合計 > 0 → ○／× |

評価文字列 = `継続率評価 + 増加数評価 + "-" + 売上増加評価`（例: `○×-○`）

**4象限の分類は「継続率評価×増加数評価」の2文字だけで決まる**（売上増加評価は表示用の参考情報で象限分類には使われていない、数式を確認して判明）:

| 継続率 | 増加数 | 象限 |
|---|---|---|
| ○ | ○ | 順調成長 |
| × | ○ | 積上純増 |
| ○ | × | ジレンマ |
| × | × | 要改善 |

象限ごとの集計値:
- 該当商材数
- 達成率 = （実績YoY売上増加が正だった商材数）／（その象限の商材数）
- 契約型／習慣型別の26年通年見通売上高合計

### 2.3 903_対目標売上・対目標スト売上相当

商材×月ごとに `見通[商材][月] - 目標[商材][月]` を売上高・ストック売上それぞれで算出するだけ（会社名・商材名は商材一覧マスタから補完）。

## 3. システム構成

```
[会社別ファイル ×50]        [目標ファイル（年1回）]
        │  ドラッグ&ドロップ            │  ドラッグ&ドロップ
        ▼                              ▼
   ┌─────────────────────────────────────────┐
   │   import.html（ブラウザ内処理）           │
   │   1. SheetJSで各ファイルをパース           │
   │   2. 商材集計シートを構造化データに変換     │
   │   3. 901/902/903ロジックをJSで計算         │
   │   4. プレビュー表示（保存前に目視確認）     │
   │   5. 「保存」→ AES-256-GCM暗号化           │
   └───────────────┬─────────────────────────┘
                    │ POST（暗号化済みJSON、合言葉ハッシュ）
                    ▼
   ┌─────────────────────────────────┐
   │  GAS Web App（新規実装）          │
   │  GitHub Contents API で           │
   │  sync/forecast-YYYYMMDD.enc.json  │
   │  を追加コミット                    │
   └───────────────┬───────────────────┘
                    │ push
                    ▼
   ┌─────────────────────────────────┐
   │  GitHub Actions → Pages 自動デプロイ│
   └───────────────┬───────────────────┘
                    ▼
   ┌─────────────────────────────────┐
   │  index.html / summary.html /      │
   │  detail.html（閲覧時に合言葉で復号）│
   └─────────────────────────────────┘
```

my_dashboard の `sync/crypto.js` / `encrypt-snapshot.js` をそのまま流用可能（暗号化ロジックは既に実績あり）。
GASからGitHub Contents APIを呼ぶ部分は、既存2プロジェクト（GAS→Notion書込）とは別系統の新規実装。

metricsは**「集計用コード＋項目名」をキーにして全項目を汎用的に取り込む**（既知の指標だけをハードコードしない）。

目標スナップショット（`sync/target-2026.enc.json`）も同一のcompanies/products構造だが、monthly値が予算数値、更新頻度は年1回。

## 5. 画面設計

`index.html`（タブ切替シェル、kokkaigiin-kankei-db と同じ構成方針）:

| タブ | 内容 |
|---|---|
| 全体サマリー | KPIタイル（グループ合計 売上高／ストック売上／ストック比率、対目標差異＋前週差異バッジ／売上高・ストック売上額はホバーで商材別の目標差異TOP5・WORST5を表示）／表示基準（単月 or 年間合計）を切り替えるピッカー／週次スナップショットの積み重ねによる自動トレンドチャート／会社別ランキング表 |
| 会社別 | 会社を選択→月次トレンド、対目標差異、`取組記入用`の施策メモ、傘下商材一覧（検索・並び替え可） |
| 商材別 | 4象限散布図（順調成長／積上純増／ジレンマ／要改善、バブルサイズ=売上規模）／対目標差異テーブル（903＋対目標スト売上を統合）／会社名・商材名・契約型で検索 |
| インポート | 週次50ファイルのドラッグ&ドロップ＋プレビュー＋保存、目標ファイルの年次アップロード枠 |

会社別・商材別は kokkaigiin の `detail.html?id=` と同じ「一覧→詳細」パターンを踏襲し、モバイルはオフキャンバスドロワーで一覧に切替可能にする。

## 6. 運用フロー

**週次（通常運用）**
1. ユーザーが50ファイルをダウンロード（現行と変わらず）
2. ダッシュボードの「インポート」タブで50ファイルをまとめてドラッグ&ドロップ
3. ブラウザが即時集計・プレビュー表示（Excelの数式張り替えが不要になる）
4. 内容確認→「保存」→暗号化→GAS経由でコミット→自動デプロイ

**年次（目標更新時）**
1. 「目標を更新」枠に目標ファイルをドラッグ&ドロップ
2. 同様にプレビュー→保存（通常の週次インポートとは独立して動作、目標が古いままでも週次インポートは影響を受けない）
